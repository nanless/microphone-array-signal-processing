# 2026-09-23 本机音频设备链路探测

这是一份**设备可见性和短时采集探测**记录，不是 AEC 收敛、ERLE、双讲、阵列空间处理或采样时钟漂移的验证。没有保存麦克风原始音频，也没有把机内麦克风称为双麦阵列。所有统计只对应这一台机器、这一次系统状态。

## 环境与设备清单

- macOS 26.6.1（Build 25G76），FFmpeg 8.1，AVFoundation 输入后端。
- 在允许访问主机设备的环境中，`system_profiler SPAudioDataType SPUSBHostDataType -detailLevel mini` 列出 MacBook Air 内置麦克风：单输入通道、当前 48 kHz；MacBook Air 内置扬声器：双输出通道、当前 48 kHz。
- USB 主机树只列两条内建 USB 3.1 总线，未列出外接 USB 音频接口或麦克风阵列。沙箱内的设备枚举为空；不能把沙箱内空清单解释成主机没有内置音频硬件。
- 主机上的 `ffmpeg -f avfoundation -list_devices true -i ''` 能列出内置麦克风；未列出其他可访问音频输入。

## 已执行的输入与播放探测

1. 短时麦克风输入：从 `:0` 捕获名义 3 秒，只运行 FFmpeg `astats` 后送往 null，不写 WAV。FFmpeg 报告输入 `pcm_f32le`、48 kHz、单声道，命令退出 0；统计窗口包含 128000 样本，整体 RMS 约 $-39.74$ dBFS，峰值约 $-18.81$ dBFS，NaN 和 Inf 数均为 0。该数据只证明有非零采集；自动增益、环境声音、采集启动边界和 FFmpeg 统计窗口均未单独标定。
2. 播放—拾音尝试：调用 `afplay -v 0.15` 播放本仓库 0.5 秒、16 kHz、单声道的合成参考 [`aec_subband_reference.wav`](audio/aec_subband_reference.wav) 一次，同时把麦克风采样经 FFmpeg 转成 48 kHz `f32le`，**仅在内存中**与线性插值到 48 kHz 的参考做滑动归一化相关。两进程退出码均为 0；收到 125568 个麦克风样本，参考展开为 24000 点，最大归一化相关绝对值约 0.0398，峰所在采集缓存索引 45134，采集 RMS 约 0.0144（数字满刻度为 1）。没有建立基线分布或重复测量，相关峰偏小，因此本次**不能确认**合成声实际经空气传播到了麦克风，更不能把峰位置换算成物理链路延迟。

两次探测没有共同硬件时间戳。`afplay` 与 FFmpeg 各自启动时刻不确定，参考经 CoreAudio 重采样，而分析端使用线性插值；因此也不能由样本数、最大相关位置或命令运行时长估计采样时钟漂移。数字参考并非采集设备的回采通道，麦克风数据也没有近端语音真值。

## 尚未完成的真实 AEC 验收

若要验证外接阵列或真实 AEC，应先连接目标设备，记录 USB 标识、固件、采样率、每台设备的物理通道与算法选择通道；在同一实验中保存获准使用的**数字播放参考与同步麦克风输入**、时间戳和增益设置，分开远端单讲、近端单讲、双讲、路径突变与静音区间。先核验延迟、极性、采样时钟和削波，再在标明适应窗口和参考对齐口径后计算 ERLE 与近端保真指标。当前硬件清单缺少目标外接设备，且这次探测没有可核验的成对音轨，所以这些项保持**未验证**。

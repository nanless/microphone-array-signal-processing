# 真实阵列录音练习 R01：相关噪声与零时延平均

这组文件取自 DEMAND 1.0 的 NRIVER 场景，是麦克风阵列实际录下的溪流水声，
不是合成语音、房间脉冲响应卷积或分别录制的单麦拼接。练习比较两路和十六路
零时延等权平均的数字功率，检验“各通道互不相关”这一简化条件。

没有干净语音参考、声源位置真值或目标说话人。本实验不计算 SNR、SI-SDR、
定位误差或语音可懂度，也不把平均后的电平下降称为语音增强效果。

官方说明第 3 节记录：16 只 Sony ECM-C10 全向麦克风接入同一台
Inrevium / Tokyo Electron Device TD-BD-16ADUSB 采集设备，阵列平面平行地面。
原始采样率 48 kHz，本实验使用上游通过 MATLAB R2012a `resample` 得到的 16 kHz 版本。
每个上游 WAV 的实际帧数是 **4,800,064**，即 300.004 秒；不能把说明中约 300 秒
直接当成文件的精确帧数。

官方 `scripts.zip` 内的 `arraypos.m` 给出四行交错排列的标称坐标。令
$h=\sqrt{0.05^2-0.025^2}$ m，各行坐标如下；每行的四个 $y$ 值依次对应通道编号。

| 通道 | $x$（m） | $y$（m） |
|---|---:|---|
| 1～4 | $0$ | 0、0.05、0.10、0.15 |
| 5～8 | $h$ | 0.025、0.075、0.125、0.175 |
| 9～12 | $2h$ | 0、0.05、0.10、0.15 |
| 13～16 | $3h$ | 0.025、0.075、0.125、0.175 |

这是上游的局部坐标，原点为通道 1；不据此定义本书的声源方位角。官方说明给出
实际安装相对标称坐标约 ±2 mm 的偏差，并明确通道增益未经相互校准。本实验保留
原始增益差，没有估计校准系数，也没有进行相位校准。

## 文件与预处理

不是搜索多个片段后选出效果最好的片段。所有文件共同导出增益为 **1**，不去直流，
不做时移，不逐文件归一化，不加抖动。平均结果只进行一次最近偶数舍入并转回 PCM16。

## R01 题目、计算与答案

将 PCM 整数除以 32768，得到数字幅度 $x_m[n]$。用 $T=160000$ 个样本计算
**未去均值的二阶矩** $R_{ij}=T^{-1}\sum_n x_i[n]x_j[n]$，不是中心化协方差。
计算前 $M$ 个通道均值的数字功率，并比较以下两种计算：

- 保留全部交叉项：$P_{\mathrm{mean}}=M^{-2}\sum_{i,j=1}^{M}R_{ij}$。
- 忽略交叉项：$P_{\mathrm{diag}}=M^{-2}\sum_{i=1}^{M}R_{ii}$。

第二种计算仍保留每个通道的实际功率，不额外假设通道等增益。
只有交叉项可以忽略时，它才与真实均值功率一致。对非零均值的信号，仅说统计独立
还不足以删除未中心化二阶矩的全部交叉项。

题目要求：复算 $M=2$ 和 $M=16$ 的上述量，读回导出 WAV 后计算
$P_{\mathrm{PCM}}=T^{-1}\sum_n y_{\mathrm{PCM}}[n]^2$，再计算
$10\log_{10}(P_{\mathrm{PCM}}/P_{\mathrm{diag}})$。
说明量化前后差异，以及为何不能把这些数字解释成 SNR 增益。

| 量 | 两通道 | 十六通道 |
|---|---:|---:|
| 通道平均二阶矩 $M^{-1}\sum_iR_{ii}$ | $1.1306449302\times10^{-5}$ | $1.0971965890\times10^{-5}$ |
| 忽略交叉项的预测 $P_{\mathrm{diag}}$ | $5.6532246512\times10^{-6}$ | $6.8574786810\times10^{-7}$ |
| 交叉项贡献 $M^{-2}\sum_{i\ne j}R_{ij}$ | $1.0304891010\times10^{-6}$ | $1.1240677806\times10^{-6}$ |
| 量化前均值功率 $P_{\mathrm{mean}}$ | $6.6837137521\times10^{-6}$ | $1.8098156487\times10^{-6}$ |
| 导出读回功率 $P_{\mathrm{PCM}}$ | $6.6837332095\times10^{-6}$ | $1.8098752073\times10^{-6}$ |
| 读回功率相对对角预测（dB） | 0.7272 | 4.2148 |
| 读回功率相对通道 1（dB） | −2.2566 | −7.9303 |

功率单位为数字满刻度幅度平方，不是 Pa² 或 dB SPL。两通道的计算例如为
$5.6532246512\times10^{-6}+1.0304891010\times10^{-6}\approx
6.6837137521\times10^{-6}$；表中最后才舍入，完整精度见清单。
均值舍入误差最大为 **0.5 个 PCM 整数单位**，因此读回功率与量化前功率略有不同。

本片段中，忽略交叉项低估了平均后的数字功率。随着通道数量增加，这一差异并未消失。
但实验没有目标信号和噪声的独立分量，也没有通道校准；数字电平下降不能证明目标保持、
语音质量改善或阵列达到了理论白噪声增益。

把同一片段依次分成十个不重叠的 1 秒块，再算相同的“读回功率相对对角预测”：

| 时间区间（s） | 两通道（dB） | 十六通道（dB） |
|---|---:|---:|
| [0, 1) | 2.3554 | 9.4000 |
| [1, 2) | 2.1631 | 8.9257 |
| [2, 3) | 1.9303 | 8.8156 |
| [3, 4) | 0.7846 | 4.8776 |
| [4, 5) | 1.2306 | 5.4636 |
| [5, 6) | 1.1798 | 2.2286 |
| [6, 7) | 0.3278 | 2.7152 |
| [7, 8) | 0.2521 | 3.4738 |
| [8, 9) | 0.4841 | 3.3094 |
| [9, 10) | 1.3646 | 5.3188 |

这些是十个相邻时间块的观测值，不是十次独立实验，不是置信区间，也不代表全部河流录音。
全段 dB 比值应先合并线性功率再取对数，不能取这十个 dB 数字的算术平均来代替。

## 离线检查与重新提取

仓库已包含四个小型 WAV（合计 6,080,176 字节），普通检查不联网、不重写资产：

```bash
.venv/bin/python codes/examples/prepare_real_recordings.py --check
.venv/bin/python -m unittest discover -s tests -p 'test_codes_real_recordings.py' -v
```

不带选项也执行只读检查。检查会核对固定原始 PCM 摘要、重新计算派生 PCM、
读回格式及全部清单指标；若本地原包存在，还逐样本核对摘录。没有原包时，检查仍能
发现摘录与已固定 SHA-256 不一致，但不会声称本次重新下载核查了上游。

显式下载和提取使用以下命令，下载约 98.7 MB，只放入 Git 忽略的缓存：

```bash
.venv/bin/python codes/examples/prepare_real_recordings.py --download
# 已有固定原包时，不联网重新提取：
.venv/bin/python codes/examples/prepare_real_recordings.py --prepare
```

固定地址为 `https://zenodo.org/records/1227121/files/NRIVER_16k.zip?download=1`。
上游公布的 MD5 为 `54264db61d3fe073fb81f2e40e0d19b5`；本书实际下载核对后的 SHA-256 为
`98e3a3f05a7234ea07619d965bafeea68a100bbce5c9269b7487393e3b559660`。
下载先写临时文件，长度和两种摘要均符合才发布缓存；已有不一致文件会报错，不覆盖。
四个输出先在临时目录生成并检查，再替换正式音频，最后写清单。若替换期间中断，
必须重新执行 `--prepare` 和 `--check`，不能把部分更新资产发布到站点。

实现见 [real_recordings.py](../array_tutorial/real_recordings.py) 和
[prepare_real_recordings.py](../examples/prepare_real_recordings.py)；固定输入、原始坐标、
处理参数、逐文件摘要、量化口径和十个时间块的完整结果见 [MANIFEST.json](MANIFEST.json)。
